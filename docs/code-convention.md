# 코드 컨벤션

## 목적

이 문서는 `Sheepy_QA_Python` 프로젝트의 코드 작성 기준을 정의한다.

기본 방향은 기존 `QA_Automation` 프로젝트의 컨벤션을 따르되, Python 프로젝트 특성에 맞게 적용한다.

## 공통 원칙

- 문자열은 쌍따옴표를 기본으로 사용한다.
- 한 줄에는 하나의 주요 문장을 작성한다.
- 연산자 양쪽에는 공백을 둔다.
- 콤마 뒤에는 공백을 둔다.
- 주석은 설명하려는 코드 위치에 맞춰 들여쓰기한다.
- 의미가 모호한 이름을 피한다.
- 테스트 코드에서도 의도가 드러나는 이름을 사용한다.

## Python 네이밍

| 요소 | 규칙 | 예시 |
| --- | --- | --- |
| 패키지 | 소문자와 언더스코어 | `sheepy_qa` |
| 모듈 | 소문자와 언더스코어 | `steam_app.py`, `process_check.py` |
| 함수 | snake_case보다 기존 프로젝트 연결성을 위해 명확한 동사형 사용을 우선하되, Python 테스트 함수는 pytest 관례에 맞춰 snake_case 사용 | `test_steam_run_uri_uses_sheepy_app_id` |
| 클래스 | UpperCamelCase | `SteamApp`, `EvidenceWriter` |
| 상수 | 대문자와 언더스코어 | `SHEEPY_APP_ID` |
| 테스트 파일 | `test_` 접두어 | `test_evidence.py` |

## 이름에서 피할 것

| 피할 이름 | 이유 |
| --- | --- |
| `Data` | 의미가 너무 넓음 |
| `Manager` | 책임이 불명확해지기 쉬움 |
| `Info` | 어떤 정보인지 드러나지 않음 |
| 과도한 약어 | 처음 보는 사람이 이해하기 어려움 |

## 테스트 코드 원칙

- 테스트 이름은 검증 대상을 문장처럼 드러낸다.
- 하나의 테스트는 하나의 핵심 기대결과를 가진다.
- 실제 Steam 게임 실행이 필요한 테스트와 순수 유틸 테스트를 분리한다.
- 환경 의존 테스트는 실패 시 `ENV_FAIL` 가능성을 먼저 검토한다.

# 최종본 범위와 완료 기준

기준일: 2026-09-14. 승인된 작업 순서는 실행 진단 → 핵심 범위 → 시작 조건 → 이미지 평가 → 반복 검증 → 제출 자료이다. 각 단계는 코드·테스트·관련 문서를 함께 작은 커밋으로 게시한다.

## 제출 범위

| 구분 | TC | 선정 이유와 완료 조건 |
| --- | --- | --- |
| 필수 실행 근거 | 001~004 | 환경·명령 호출·프로세스·캡처를 구분하고 동일 시작 조건에서 3회 기록 |
| 필수 플레이 흐름 | 019, 010, 006, 011 | 로비 준비와 진입, Space·방향키의 시각 반응. 각 TC마다 시작 상태 복원 후 3회 |
| 필수 짧은 안정성 | 007, 012 | 관찰 구간의 프로세스와 연속 무변화 후보를 기록. 프리즈 부재나 장시간 안정성으로 일반화하지 않음 |
| 증빙 지원 | 008 | 게임 없는 파일 검증이며 실제 게임 통과율에 합산하지 않음 |
| 환경별 선택 | 005, 009, 017, 018 | 검은 화면·언어 화면이 실제 나타나는 조건에서만 검증 |
| 후속 범위 | 013~016 | 신규/기존 저장 상태, 파일 경로, 복합 입력. 핵심 검증 완료에 포함하지 않음 |
| 수동 탐색 | 메뉴 진입·복귀 | 기존 TC-019는 로비 CTA 후보 검사로 메뉴 복귀 검증을 대체하지 않음. 실제 관찰 후 절차를 확정 |

범위 제외는 통과가 아니다. 전체 TC 추적표의 미실행 기록은 유지한다. 신규 세이브 생성이나 기존 세이브 삭제·수정 없이 가능한 시작 장면을 사용한다.

## 단계별 게이트

1. **실행 진단**: 수동/자동 실행 차이, 프로세스·창·소요 시간·실패 원본을 남긴다. 시작 전 게임 미실행 상태에서 3회 실행·탐지 성공해야 완료한다. 기존 프로세스 재감지는 새 기동 성공이 아니다.
2. **시작 조건**: 빌드·해상도·배율·창 모드·언어·시작 장면과 수동 준비 절차를 기록한다. 모르는 화면과 포커스 이탈 시 입력 중단을 확인한다.
3. **판정 평가**: 입력 없음/정상 반응/메뉴 전환/포커스 이탈 표본에 사람이 정답을 붙인다. 조정용과 평가용을 분리하고 오탐·미탐·보류를 집계한다. 표본이 없으면 정확도를 표시하지 않는다.
4. **반복 검증**: 필수 TC별 같은 조건 3회, 실행 ID·기대/실제·원본 증거를 보존한다. 실패 후 재시도를 최초 성공으로 합치지 않는다.
5. **제출**: 대표 정상 흐름과 실패 진단 사례를 공개하고 README·진행표·완성도를 실제 결과와 맞춘다. 필요한 회귀와 최신 CI 통과를 확인한다.

## 이전 기동 진단

2026-09-14 프로세스 조사에서 Steam 창 제목 `Steam Error`가 관찰됐다. Computer Use에서는 Steam의 조작 가능한 창을 찾지 못했고 기존 설치 경로 실행도 창을 노출하지 않았다. 이 사실만으로 오류 내용이나 원인을 확정할 수 없다. 수동 실행과 오류 문구 확인을 요청했으며 반복 기동을 중단했다. 게임 파일·세이브·Steam 설정은 변경하지 않았다.

핵심 게임 검증은 준비 대기, 코드·진단 증거·평가 도구 보완은 진행 가능하다. [현재 상태](progress.md), [실제 실행 이력](local-verification.md).

후속: 사용자 수동 실행 후 프로세스와 창 존재를 확인했다. 현재 차단점은 Computer Use 화면 캡처의 0x80004002 오류이며 입력 없이 TC-001/003만 재검증했다. [분리된 실행 기록](local-verification.md).

[추가 실제 게임 진단과 남은 결함](live-validation-2026-09-14.md). 캡처는 desktop 권한의 프로젝트 API로 재개했으며 도구 캡처 오류와 분리한다.

위 단락은 9월 14일 당시 기동 진단 이력이다. 현재 완료 여부와 다음 검증 항목은 [현재 상태의 남은 필수 작업표](progress.md#남은-필수-작업), 최신 실제 실행은 [9월 15일 재검증](live-validation-2026-09-15.md)을 따른다. 과거 준비 대기 상태를 현재 차단점으로 이월하지 않는다.

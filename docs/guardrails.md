# 테스트 수행 가드레일

## 목적

이 문서는 Sheepy 자동화 QA를 수행할 때 지켜야 할 제한사항을 정의한다.

## 기본 원칙

1. Steam 게임 파일을 임의로 수정하지 않는다.
2. 게임 실행 결과를 바꾸기 위한 비정상 조작을 하지 않는다.
3. 안티치트 또는 보안 기능이 있는 게임에는 자동 입력을 적용하지 않는다.
4. 자동화는 개인 로컬 QA 학습 목적으로만 사용한다.
5. 테스트 기대결과는 실행 중 변경하지 않는다.
6. 실패를 없애기 위해 PASS/FAIL 기준을 완화하지 않는다.
7. 실패 시 screenshot, process state, log를 저장한다.
8. 원인이 불명확하면 제품 문제로 단정하지 않고 `REVIEW_REQUIRED`로 기록한다.

## 실패 분류 원칙

| 분류 | 기준 |
| --- | --- |
| `PRODUCT_FAIL` | 게임 기대 동작과 실제 관찰 결과가 명확히 다름 |
| `TEST_FAIL` | 자동화 입력, 이미지 인식, 테스트 절차 문제가 의심됨 |
| `ENV_FAIL` | Steam, 설치, 실행 권한, 프로세스, OS 환경 문제가 의심됨 |
| `REVIEW_REQUIRED` | evidence가 부족하거나 분류 근거가 명확하지 않음 |

## 하네스와 루프 적용 전 원칙

초기 단계에서는 하네스와 루프를 의도적으로 적용하지 않는다.

반복 코드, 불안정한 대기, 중복 evidence 수집, 실패 분류의 어려움이 실제로 나타나는지 확인한 뒤 적용 여부를 판단한다.

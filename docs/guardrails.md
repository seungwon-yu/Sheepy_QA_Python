# 실제 게임 검증 기준

게임 실행·관찰과 수정 작업을 구분한다. Steam 게임 파일과 사용자 세이브를 임의 수정/삭제하지 않는다. 실행 중 기대값을 바꾸지 않는다. 실제 입력은 Sheepy 창인지 직전에 확인하고 알 수 없는 상태에서 키를 반복하지 않는다.

명확한 자동화 코드 결함은 재현 기록 후 수정하고 재검증한다. 입력/캡처/이미지 기준 문제를 게임 결함으로 단정하지 않는다. 증거 부족은 REVIEW_REQUIRED로 남기며 통과율에 포함하지 않는다.

사전조건 준비는 LANGUAGE→LOBBY→GAMEPLAY 후보의 관찰된 전환만 지원한다. 언어/로비 각각 Enter는 최대 한 번, 기본 15초 제한이다. 검은 화면은 재관찰하고, 포커스 상실·알 수 없는 화면은 중단한다. 임의 게임 화면에서 로비로 강제 복귀하거나 저장 상태를 초기화하지 않는다.

실제 게임을 실행하기 전 [환경 프로필](environment-profile.md)을 기록한다. 중단 조건과 입력 범위를 사람이 이해해야 한다. 기본 CI는 게임을 실행하지 않는다.

GAMEPLAY 후보는 2초 연속 관찰 후 준비 완료로 인정한다. 중간에 로비·검은 화면이 보이면 연속 시간을 초기화한다. 이는 순간 전환 오판 완화이며 실제 플레이 판정의 정확도 보장은 아니다.

현재 Continue 프로필은 로비 Enter 후 BLACK 관찰을 거친 뒤 연속 GAMEPLAY 후보를 허용한다. 로딩 프레임이 관찰되지 않으면 보류하며 이를 다른 빌드의 일반 규칙으로 주장하지 않는다.

로컬 준비 한도는 30초이다(순수 helper 기본값은 15초 유지). 실제 Continue 관찰에서 BLACK 이후 GAMEPLAY 후보가 14.531초에 나타나 2초 연속 확인이 기존 한도를 넘었다. 이는 준비 대기 예산이며 30초 이내 기동 성능 합격 기준이 아니다. 이전 타임아웃 결과를 보존한다.

동일 LocalScreenSession에서는 첫 캡처 크기를 기준으로 유지한다. 이후 크기가 바뀌면 SCREEN_SIZE_CHANGED 증거(기대/실제 크기·이미지 경로)를 기록하고 화면 분류·이미지 비교 전에 준비를 중단한다. 새 크기로 자동 보정하거나 로비 기준을 갱신해 계속하지 않는다. 실제 재시도는 시작 화면을 다시 확인해 새 세션으로 수행한다.

관찰·Enter·대기 콜백 예외는 UNKNOWN/준비 실패로 처리하되 이전 이벤트를 유지한다. ENTER_ATTEMPT는 입력 시도이며 ENTER는 콜백 정상 반환이다. 입력 예외가 발생하면 일부 키 이벤트가 전송됐을 수 있어 입력 부재로 단정하지 않는다. 오류 이벤트에 단계·예외 종류·메시지·직전 상태·경과 시간을 기록한다.

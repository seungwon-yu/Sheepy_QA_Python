# 작업 순서의 이유

이전 Sprint 1~7은 개발 이력이며 현재 완료 기준은 [진행 상태](progress.md)에 모은다. 신입 포트폴리오에서는 위험이 큰 진입·입력·관찰 신뢰성을 우선한다.

1. 환경/실행 명령/프로세스를 분리해 실행 불가 원인을 설명한다.
2. 화면·창 포커스를 확인해 잘못된 입력과 캡처를 줄인다.
3. 언어 선택→로비→플레이 후보의 사전조건을 준비한다.
4. 무입력 대비 입력 변화·연속 무변화 시간을 관찰한다.
5. 반복 결과와 한계를 사례로 작성한다.

TC 개수나 프레임워크 규모는 완료 기준이 아니다. 준비 helper는 중복과 상태 오염이 확인되어 도입한 것이며 엔진 하네스 도입을 목표로 하지 않는다.

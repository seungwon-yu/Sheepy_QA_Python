# 커밋 기준

한 커밋은 하나의 검토 가능한 변경 이유를 갖는다. 타입은 `Fix`, `Test`, `Docs`, `Refactor`, `Chore`, `Feat`를 사용하고 제목·본문은 한글로 작성한다.

```text
Fix: 판정 근거 누락 시 통과 방지

필수 신호가 없어도 통과하던 문제를 검토 상태로 처리한다.
재현 입력과 수정 후 회귀 결과를 함께 기록한다.
```

본문에는 문제의 조건, 변경 후 동작, 검증 명령과 결과를 적는다. 미실행 검증은 미실행이라고 쓴다. 테스트 수 증가만을 개선 효과로 주장하지 않는다. 관찰 범위나 기대결과 계약이 바뀌면 관련 TC·판단 문서·추적표도 함께 변경한다.
